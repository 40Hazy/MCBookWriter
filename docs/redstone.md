# 红石补给与收书方案

## 原理

AutoBook 只做两件事与物流相关：

1. **消耗**背包中的空的书与笔。
2. 完成后成书留在当前选中槽（默认），或在 `keepWrittenBooks=false` 时整栈丢出。

因此红石系统需要：

- 持续向玩家补充空书；
- 把成书从玩家身边带走。

物品实体在玩家附近会自动被拾取；漏斗不能直接向玩家背包插入物品，所以“补给”通常用**投掷器**把空书以物品形式丢到玩家脚下。

## 方案 A：全自动（推荐用于长任务）

```text
      [投掷器]  ← 红石时钟
          │ 丢出空的书与笔
          ▼
       [玩家]  ← 站在漏斗上
          │ 成书整栈丢出（keepWrittenBooks=false）
          ▼
       [漏斗] → [箱子]
```

搭建要点：

1. 玩家站位脚下放漏斗，漏斗输出到旁边箱子。
2. 投掷器朝向玩家脚下，装填空的书与笔，用红石时钟周期性触发。
3. 漏斗上方保持无遮挡，确保丢出的成书能被漏斗吸走。
4. 玩家周围用方块围住，避免物品弹飞。
5. 配置：

   ```json
   {
     "keepWrittenBooks": false
   }
   ```

   修改后下次 `/autobook start` 或 `resume` 生效，无需重启。

注意事项：

- 投掷器每次只丢 1 本，时钟频率不要太高，避免地面堆积。
- 玩家丢出的物品对本人有短暂拾取延迟，漏斗可以先于玩家收走成书。
- 部分服务器会清理地面物品或限制投掷器，先跑 `autobook-test` 验证。

## 方案 B：半自动

保持 `keepWrittenBooks=true`（默认），成书留在背包：

- 空书由投掷器/手动补充；
- 每写完若干本，玩家自己把成书存进箱子或末影箱，腾出槽位。

优点是不依赖丢物品与漏斗，服务器兼容性最好；缺点是长时间运行需要人工清背包。

## 方案 C：纯手动补给

完全不搭红石：

- 开跑前按 `/autobook plan` 显示的本数准备空书（三体1打包后约 12 本，不再需要 36 本）。
- 空书不足时模组自动进入 `SUPPLY` 暂停；
- 手动补书后模组自动继续，不需要命令。

适合首次测试或小任务。

## 暂停与恢复行为

| 情况 | 模组行为 |
| --- | --- |
| 背包没有空书 | 进入 `SUPPLY` 暂停，每 20 tick 检查一次 |
| 拾取到空书 | 自动继续，无需命令 |
| 背包被成书占满 | 找不到空书，按上一行处理；需先清出槽位 |
| `/autobook pause` | 当前书写完后暂停，避免半成品 |
| `/autobook stop` | 终止整条运行（CANCELLED），立即停止并保留进度 |

## 容量估算

以三体1为例：

- 跨章节打包后约 12 本成书（按 100 页/本），占 12 个物品槽；
- 旧版按章节分本时为 36 本，会占满整个背包；
- 即使降到 12 本，长任务仍建议使用方案 A 或定期清理背包。

## 安全建议

- 先用 `autobook-test` 跑通，再跑正式任务。
- 红石系统先在单人/测试服验证，再上正式服。
- 不要把投掷器对准边界外或岩浆，避免空书丢失。
- 不要在运行期间打开箱子/背包界面，模组会等待界面关闭。
